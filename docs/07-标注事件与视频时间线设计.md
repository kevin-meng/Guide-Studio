# Guide Studio · 标注事件记录与视频生成时间线设计（讨论稿 V0.1）

> 状态：**设计讨论 / 未实现**。分支：`design/annotation-timeline-v1`。基线：`feat/guide-studio-v1`。日期：2026-10-11。  
> 核心目标：当前像微信截图一样简单地制作图文教程，后台自动保留“出现顺序”；未来基于同一份可编辑内容生成短视频操作教程。**不要把编辑操作历史直接当成视频剧本。**

## 1. 范围与现状核对

目前 `web/canvas.js` 中 `AnnotationCanvas` 对 `step.annotations[]` 直接增删改；`snapshot()`、`undo()`、`redo()` 只是最多 35 份内存快照；`down/move/up` 处理手势；`exportStep` 把最终画面压平成 PNG。`web/app.js` 中 `newStep()` 默认只有 `annotations[]`；`changed(true)` 只负责标记公开图片失效与延迟本地保存；`syncGuide()` 序列化最终 `annotations[]` 到 `Guide.steps` JSON；`server/db.py` 的 `GuidePublication.steps` 仅存公开压平图。这意味着目前**没有可靠的持久事件序列，也没有视频播放时间线**。

首轮讨论目标：
- **要记录**：标注创建顺序、稳定对象 ID、绘制坐标/路径、操作类型、最终状态、修改删除关系、必要时间信息、步骤顺序和步骤文案。
- **暂不开发**：录屏、摄像头录制、AI 配音、完整视频编码服务、视频商业化。
- **不应记录**：每一帧 UI 重绘、鼠标随意游走、键盘每一次输入、设备指纹、与教程无关的用户行为。
- 既有的无记录教程仍然能正常编辑、导出 PNG/HTML 与发布。

## 2. 一个关键区分：三种信息不要混在一起

| 层 | 真正回答的问题 | 主要数据 | 是否对外 |
| --- | --- | --- | --- |
| **A. 画面快照 Scene** | 最终要显示哪些标注？ | 源图引用、annotations（类型/位置/样式/文字/层级） | 内部私有，公开仅压平图 |
| **B. 编辑事件 Edit Events** | 作者实际上先做了什么、又怎样修改？ | append-only 添加/修改/删除/撤销事件与提交顺序、少量笔画采样 | **作者私有**；用于恢复与审计，不能直接公开视频 |
| **C. 演示时间线 Presentation Timeline** | 观众按照什么顺序、速度看到标注？ | clip、cue、atMs、durationMs、effect、旁白/字幕 | 用于私有预览；发布视频时只公开最终视频文件 |

**推荐：自动采集 B，先依据 A 和 B 生成 C，用户仅在需要制作视频时调整 C。** 日常做图文教程仍只有“截图—标记—写步骤—保存”。

举例：作者先圈错位置、撤销、重新画圆，再加箭头。真实历史 B 必须保留错误与撤销；最终视频 C 默认仅播放正确的圆与箭头，不重放失败尝试。标注拖动位置后，默认视频使用**最终坐标**，不播放纠错时的来回拖动。

## 3. 建议记录哪些字段？

### 3.1 标注对象（最小必做）

沿用 V1 标注格式，在每个对象加上稳定元数据，避免改变现有绘图类型：

| 字段 | 语义 | 要求 |
| --- | --- | --- |
| `id` | 标注对象 UUID；移动或修改后不变，复制时新建 | 必须 |
| `type` | circle/rect/arrow/pen/text/number/mask | 已有 |
| `x,y,w,h,x2,y2,points` | 归一化几何数据（按图元不同） | 已有 |
| `color,width,fontSize,text` | 样式、文字 | 已有 |
| `zIndex` | 最终叠放顺序；与视频先后顺序不同 | 建议 |
| `createdSeq` | 本步骤首次创建的**逻辑序号**，跨页面/设备同步不变 | 必须 |
| `createdAt` | UTC 时间（辅助排错，不负责播放排序） | 建议 |
| `strokeSamples` | 仅自由画笔可选：`[x,y,tOffsetMs]` 压缩采样，沿路径动画 | 可选 |
| `replayHint` | fade/draw/pop等作者偏好；不承载具体时间轴 | 可选 |

**注意**：不在每个标注存绝对屏幕像素；使用 0–1 坐标，导出时按原图尺寸换算。视频布局时再适配 9:16、16:9；不得让纵横比变化扭曲图形。图片替换后需要复核坐标与隐私遮挡。

### 3.2 编辑事件（完整但低成本）

建议每一次**已提交的操作**记录一条，而不是每次 `pointermove` 都写数据库。

| 字段 | 语义 | 要求 |
| --- | --- | --- |
| `eventId` | 事件 UUID，保证重试去重 | 必须 |
| `guideId / stepId` | 所属教程及步骤 | 必须 |
| `sessionId` | 当前编辑会话 UUID，区分多设备 | 建议 |
| `seq` | 步骤内单调递增的逻辑序号，优先于时间戳用于排序 | 必须 |
| `action` | `annotation.add/update/delete`、`undo/redo`、`step.reorder` 等 | 必须 |
| `objectId` | 被操作对象 UUID；教程级动作可为空 | 条件 |
| `before / after` | 事务前后**最小必要对象状态**，支持重放与撤销 | 条件 |
| `at` | UTC ISO 时间，仅分析/审计 | 建议 |
| `gestureDurationMs` | 真实画笔/拖拽手势持续时间，不含长时间停顿 | 可选 |
| `strokeSamples` | 仅 pen 需要的绘制路径采样与相对时间 | 可选 |
| `sourceRevision` | 基于哪个云端 revision 编辑，冲突处理 | 建议 |

事件提交边界：
1. 画形状：`pointerdown` 至 `pointerup` 合并为一个 `annotation.add`；无效点击不写入。
2. 移动/缩放：一轮完整拖动合并成一个 `annotation.update`；不存上百条 move 事件。
3. 文本：对话框按“确定”后才提交；取消不写。
4. 删除：`annotation.delete`；撤销/重做记录为语义事件或其逆操作，并在聚合时保持最终状态正确。
5. 颜色/样式：**仅选择颜色但没修改对象**不记为内容事件。
6. 更换截图：`image.replace` 并使时间线/视频缓存失效；不将整张图片 bytes 混入事件。
7. 步骤新增、删除、排序、说明变更：可以记录在教程级简化事件里，但初期只需保证最终步骤顺序和文案存在；避免字字键入事件。

事件用于**真正的创作历史**，不是公开视频动画指令。错画、删除、撤销都可能出现在 B，但**默认不出现在 C**。做用户动作分析时应当匿名/聚合，严格限制保留期。

### 3.3 视频播放意图（与编辑过程解耦）

在每个 `step` 下可选添加 `presentation`：
- `schemaVersion`：协议版本，当前设计为 1。
- `durationMs`：当前步骤视频时长。
- `cues[]`：某个标注在 `atMs` 时以什么动画进入，`durationMs` 多长。
- `subtitle`：默认来源于 `step.description`，可手动改写；不依赖截图里文本。
- `voiceover`：未来可选，包含音频资产 ID、开始时间、时长，当前不要求生成。
- `transition`：进入/离开下一截图的过渡样式。
- `videoSettings`：教程级输出配置：画布纵横比、分辨率、帧率、背景、安全边距、字幕规则。

`cues[]` 引用 `objectId` 而不是数组下标；**最终排序以 `cues.atMs` 为准**，不是 `createdAt` 或原始 `seq`。删除标注时对应 cue 需清理；移动标注时 cue 不变但使用最终位置。

建议默认生成算法：截图入场（约 0.3 秒）→ 操作说明停留（约 0.5 秒）→ 按 `createdSeq` 对每个有效、非隐私遮挡标注分配间隔（约 0.5–0.8 秒）→ 最后停留约 0.8 秒 → 下一步。**上述秒数是初版默认值，不是编辑所花时间。** 内容过长可按旁白长度重排；用户以后可拖动时间线调整。

## 4. 隐私与内容正确性（必须先于视频功能）

现有 `mask` 是非破坏性编辑图层，原图在私有素材中可能仍可见。**若视频从未遮挡原图开始播放，再让遮挡动画“出现”，会泄露被遮挡内容。**

严格规则：
1. **每一帧**必须以“原图 + 所有有效 mask 的最终遮挡”生成**已脱敏底图**，然后才动画显示圆圈、箭头、普通文字与序号。
2. 隐私 mask 默认不参与出现动画；不能在视频的任何一帧显示遮挡之前的源图。
3. 发布视频只允许读取权限校验通过的素材与渲染产物；事件日志、原始图、私有图层数据不进入匿名 API。
4. 调整/删除隐私遮挡、替换原图、修改步骤文字、修改时间线都要使视频输出标记为过期，重新安全审查并重渲染。
5. 发布前执行视频帧采样/审核验收；如果需要真正不可逆匿名化，公开导出永远只用压平后的去敏影像。
6. 字幕、旁白、封面图以及媒体元数据也需要单独做隐私复核；不能只检查视频画面。

## 5. 与当前 V1 的兼容和落库

### 5.1 短期：低成本扩展现有 `Guide.steps`

`annotations[]` 仍是最终可编辑图层；新增标注对象字段 `id/createdSeq/createdAt`；`step.presentation` 暂时可选。原图 `imageData` 仍仅在浏览器本地，不进入后端 JSON。公开 `GuidePublication` 保持只存压平 `publicAssetId` 和说明。

**操作历史不要无限塞进 `Guide.steps` JSON**：当前服务端 `GuideInput.steps` 限制最多 60 个步骤，并通过 PUT 整体保存，写入庞大事件/笔画路径会严重影响同步、冲突率和体积。

建议新增本地 IndexedDB 对象仓库 `annotation_events`（v1 数据库需升级版本并在 `onupgradeneeded` 处理），用 `guideId+stepId+seq` 索引，批量去抖保存。云端需要跨设备恢复全部历史时，再新增 `annotation_events` 表，建议包含：
`id, workspace_id, guide_id, step_id, event_id, session_id, seq, action, payload_json, source_revision, recorded_at`；
索引 `(guide_id, step_id, seq)`；事件权限与 Guide 一致。**不能只靠客户端生成的 seq 解决多人冲突**：继续使用现有乐观锁 revision，上传时由服务端验证基础版本/排序并去重；冲突留在本地待人工解决。多步重排使用稳定 step UUID。

为避免业务库膨胀，可对笔画路径降采样、设置历史存储配额与留存周期；如需长期留存可按 revision 冷存储在私有 COS。**跨设备视频生成最低需要同步“最终图层+顺序+演示时间线”，完整原始编辑历史可作为可选同步项。**

### 5.2 老教程迁移

旧数据中缺少 `id` 和 `createdSeq` 时：
1. 读取时规范化，给每个标注生成并持久化稳定 UUID。
2. 依据当前 `annotations[]` 数组顺序合成 `createdSeq=1..N`；这只是**推断的默认播放顺序**，不是历史事实。UI 需可调整顺序。
3. `editEvents=[]`；`timelineSource="inferred-legacy"`；不伪造过去的编辑时间或笔画路径。
4. 用户首次编辑后开始记录真实事件，旧截图/PNG/HTML 功能维持原样。
5. 需要 Alembic 数据库迁移，而不是依赖已有 `create_all` 自动加表。

## 6. 未来的视频制作体验（建议）

默认仍只看见“做图文教程”。完成标注后可点 **「预览演示」**，自动生成下面的轻量时间线：

`进入步骤截图 → 高亮/画出第一个标注 → 第二个标注 → 显示/持续字幕 → 下一步截图`

后续才开放「视频设置」页：
- **顺序**：在卡片列表拖动标注出现顺序，不要求专业剪辑知识。
- **动效**：圆圈描边、箭头延伸、序号弹入、普通文字淡入。
- **节奏**：整体“快速/标准/详细”三档；高级用户可设置单个 cue 时长。
- **旁白**：先支持字幕与静音视频；以后提供语音录制或 TTS。
- **尺寸**：竖屏 9:16 适合微信/视频号/小红书；横屏 16:9 适合知识库及电脑。
- **品牌**：Guide Studio / Yanxu 可配置 LOGO、片尾，项目级默认设置。
- **智能自动化**：未来可在用户许可下依据步骤描述生成分镜与旁白，但结构数据才是权威来源。

一篇教程可能包含 3–10 张截图，无需再逐帧编辑；**用户可保留图文教程与视频两个发布物**，二者独立版本化。

## 7. 视频技术路线与权衡

| 方案 | 优势 | 限制 | 建议 |
| --- | --- | --- | --- |
| **Canvas 时间轴预览**（仅播放，不编码） | 用现有 Canvas，跨平台成本低 | 不是下载的视频 | **先做，P1** |
| `canvas.captureStream()` + `MediaRecorder` | 借用客户端算力，端上编码、服务器零渲染 | 不同浏览器支持的 MIME/容器不同，实时录制速度与帧稳定性有限 | **优先验证桌面 P2**，运行时 `MediaRecorder.isTypeSupported` 探测 |
| WebCodecs `VideoEncoder` + muxer | 可以精确指定帧时间、优化离线渲染 | 不是所有浏览器可用，HTTPS 和复用器依赖、编码格式差异 | **性能路线实验**，特性探测 |
| ffmpeg.wasm | 浏览器内封装/转码灵活，不传源图 | 移动端下载体积大、内存与耗时负担显著 | 不作为移动端默认方案 |
| 服务端 FFmpeg / 任务队列 | 高质量、稳定 MP4、离线批量生成 | 服务器成本；上传原素材触及隐私边界 | 商业化或跨端一致性需要时采用，需明确授权 |

参考：MDN `https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/captureStream`、`https://developer.mozilla.org/en-US/docs/Web/API/VideoEncoder`；ffmpeg.wasm `https://ffmpegwasm.netlify.app/docs/performance/`。**不能假设微信内置浏览器能够稳定产出 MP4**；必须做 iOS 微信、iOS Safari、Android 微信、桌面浏览器真机验证。视频封装/视频轨/音频轨兼容性在实际导出时探测，失败时保留图文和预览能力。

## 9. 需要决策的 4 件事

1. **默认视频风格**：推荐“干净的教学演示”（只让最终正确标注依次出现），不是“真实作者录屏”（包含错误/撤销）。
2. **视频轨迹**：圆圈/箭头记录最终参数即可生成描边；只有自由笔需要额外记录绘制路径及可选真实时间。
3. **历史保留**：建议最终图层和可播放 cue 长期保存；原始完整编辑事件有限期保留、默认私有。其用途是恢复/审计，不是公开视频依赖。
4. **视频版本**：图文教程可先发布，视频作为独立产物，可晚于正文生成、失效、更新，不改变教程稳定链接。

---

**结论**：现在必须补的不是“录像”，而是**每个图形稳定 ID + 创建序号 + 关键编辑事件 + 独立演示时间线**。以当前 V1 的非破坏性标注结构增量实现即可，不必推倒重来。
