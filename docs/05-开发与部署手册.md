# Guide Studio · 开发部署与 COS 对接手册 V1

## 1. 最小环境

Python 3.11+、pip、Web 浏览器、可选 Docker 与 PostgreSQL。前端**无 npm 依赖或构建命令**，静态 ES Modules 由 FastAPI 同源托管。运行 `python -m pytest -q` 需 pytest 和 httpx，可在开发环境安装。

### 本地开发

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# 必须编辑 .env 中的 SESSION_SECRET 和 BOOTSTRAP_ADMIN_*
set -a
source .env
set +a
uvicorn server.main:app --reload --port 8000
```

地址：http://localhost:8000 。公共阅读 `/g/{slug}`，健康检查 `/api/health`，OpenAPI `/api/docs`。

### 本地业务验证

1. 工作台 → 新建教程 → 多图导入 → 图上画红圈 / 箭头 → 写步骤 → 返回列表 → 再打开，确认草稿仍在。
2. 导出 PNG、离线 HTML 并在无网络时打开 HTML。
3. 使用管理员邮箱与密码登录 → 云端保存 → 发布 → 复制公开链接 → 用匿名窗口打开。
4. 返回编辑器修改文字和截图，但不发布，匿名窗口刷新确认仍是旧版；重新发布确认新内容更新。
5. 录入常见问题、关联已有教程，验证不会创建重复教程。

## 2. 正式部署方案

推荐：HTTPS 反向代理（Nginx/Caddy/EdgeOne）→ FastAPI Docker → PostgreSQL 16 / 私有 COS。前端页面和 API 必须同源，避免浏览器 cookie 跨域兼容问题。反代需传递标准 `Host` 和 `X-Forwarded-Proto`，启用严格 HTTPS。示例：

```bash
cp .env.example .env
# 配置 SECRET、管理员初始账户、POSTGRES_PASSWORD、PUBLIC_BASE_URL
# 生产模式 DATABASE_URL 由 docker-compose 写为 postgresql+psycopg://...
docker compose up -d --build
docker compose logs -f app
```

**上线前清单**：管理员初始密码唯一且强、SESSION_SECRET 随机 ≥32 字符、HTTPS、可信反代、数据库定时备份、对象存储权限、基础请求限速、防爆破、错误监控、权限测试通过。建议生产中关闭 `/api/docs` 对公网可见、配置 CSP/安全响应头及严谨的访问审计。Docker Compose 示例侧重开发/小团队部署，不等同于完成安全加固。

## 3. COS 连接

目前 `server/storage.py` 通过 boto3 S3 兼容接口支持 Tencent COS；上传由后端服务代理，匿名访问经授权后使用短效签名 URL。必须创建**私有读写**存储桶，禁止公共写权限，不能在前端暴露任何 SecretId/SecretKey。

`.env` 示例（全部使用占位值）：

```dotenv
STORAGE_BACKEND=cos
COS_BUCKET=your-private-bucket-1250000000
COS_REGION=ap-shanghai
COS_ENDPOINT=https://cos.ap-shanghai.myqcloud.com
COS_ACCESS_KEY_ID=from-server-secret-manager
COS_SECRET_ACCESS_KEY=from-server-secret-manager
COS_SESSION_TOKEN=
```

生产建议由腾讯云 CAM 最小权限策略仅允许对应桶/指定前缀的 `PutObject`/`GetObject`/`HeadObject` 等必需操作。当前按 Workspace UUID 将不同工作空间资产放入独立前缀。COS 实桶接口/地域签名、跨域、上传较大文件需要部署后联调。未来升级 STS 临时密钥直传：服务端验证登录、签发指定前缀与大小范围的受限凭据，浏览器直传后服务端 HEAD 验证对象，再标记 ready，拒绝自报 key 越权。

## 4. 数据库迁移与备份

当前 `Base.metadata.create_all(engine)` 只会建缺失表，**不会修改现有表字段**；上线后的 schema 变化必须引入 Alembic，禁止直接丢库重新创建。PostgreSQL 建议定期 `pg_dump -Fc`，每季度演练恢复；COS 备份/版本化策略独立配置。导出教程 HTML 只能作为内容级备份，不能替代数据库备份。

## 5. 账号与协作

初始化管理员凭据从环境变量读取，只在 users 表为空时创建一次。没有开放注册接口。管理员可在 Swagger 认证 cookie 后调用 `POST /api/members` 创建编辑者/审核者。请求：

```json
{"workspaceId":"<workspace uuid>","email":"volunteer@example.com","displayName":"志愿者A","password":"temporary-secret-at-least-12","role":"editor"}
```

当前没有完整 UI 成员管理、密码重置、用户邀请邮件；不要把初始密码发送到公开群聊。正式推广前应增加邀请链接、登录限速与密码重置机制。

## 6. 安全与隐私注意事项

- 公开链接的发布对象必须是压平后的 `export` 图片，绝对不能发布可逆图层和原始 PNG。
- 原图只对 Workspace 已授权成员开放。暂未实现独立数据清除 UI，要求内测阶段避免上传真实个人隐私数据。
- `mask` 是纯色覆盖；使用模糊/透明可能发生残留数据泄露。
- 服务端 MIME 魔数与大小限制只做基础防御，正式环境应再做解码验证、恶意图像防护、图片尺寸限制与杀毒扫描。
- 登录 Cookie HttpOnly + SameSite Lax + HMAC 签名，修改请求检查 Origin；正式生产还应增加 CSRF token/严格 Referer 兜底、速率限制、用户会话失效列表和安全告警。
- 使用多副本部署时，SQLite、本地图片目录都不适合，必须统一 PostgreSQL + COS。

## 7. 故障排查

- `SESSION_SECRET must contain at least 32 characters`：确保从 `.env` 正确导出环境变量。
- `BOOTSTRAP_ADMIN_*`：全新数据库初始化必须提供安全凭据；已有数据库不重新覆盖已有用户密码。
- 401：需要登录；403：权限或 Origin 检查；409：与远端 revision 不一致；422：图像/步骤内容校验失败。
- 图片不显示：检查存储类型、COS endpoint/region、桶私有权限、资产是否被当前用户或公共快照授权。
- 本地草稿丢失：检查是否切换浏览器、无痕模式或清除站点数据；依赖 IndexedDB 时需告知用户备份风险。
